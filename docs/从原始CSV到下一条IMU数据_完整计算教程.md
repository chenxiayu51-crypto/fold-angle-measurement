# 从原始 CSV 到下一条 IMU 数据：当前模型究竟怎样计算

如果对 h、e1/e2 的朝向、时间拟合或梯形积分还不清楚，先看补充的[手机实景与坐标图解](手机铰链轴与IMU角度计算_六个问题图解.md)：用真实照片、7 张图和原始 CSV 行逐项解释。

本文只沿着一条计算链讲：**原始 CSV → 按传感器拆分 → 去重和时间转换 → 初始化参数 → 一条一条更新角度 → 新数据如何继续用**。先把固定底座主结果算通，再说明双 IMU 的改动。

所有数值对应 `data/raw/sensor_log_2026-10-16_11-04-53.csv`。这里没有训练神经网络。当前的“模型”是带有明确公式、参数和历史状态的单自由度物理估计器；也没有实现卡尔曼滤波。视频只为本次初始化和实验对照提供帮助，后面的每一步角度更新并不持续读取视频。

## 1. 打开最原始 CSV：一行到底是什么

原文件开头是：

```csv
timestamp_ns,delta_ms,sensor,x,y,z,w
54192337235780,10.0,加速度传感器,-0.0717,0.1230,9.7992,0.0000
54192341235624,10.0,陀螺仪传感器,-0.0037,0.0061,-0.0010,0.0000
54192347234686,10.0,加速度传感器,-0.1091,0.1242,9.8023,0.0000
54192351234530,10.0,陀螺仪传感器,-0.0066,0.0094,-0.0009,0.0000
1792119894952000000,15.0,gyro1,0.0083,0.0418,-0.0036,0.0000
1792119894952000000,16.0,acc1,-5.3981,0.0143,-8.2200,0.0000
1792119894952000000,,acc1,-5.3981,0.0143,-8.2200,0.0000
1792119894952000000,,gyro1,0.0083,0.0418,-0.0036,0.0000
```

这是一张四路传感器交错写入的长表。**一行是某一个传感器的读数，不能把连续四行直接当成同一时刻的四路输入。**

| 列 | 本次如何解释和使用 |
|---|---|
| timestamp_ns | 整数纳秒时间戳；计算采样时间和 dt 的依据 |
| delta_ms | 日志附带的间隔字段；可能为空，当前估计器不用它作积分步长 |
| sensor | 决定该行属于哪一路传感器 |
| x,y,z | 对 Acc 是三轴加速度，对 Gyro 是三轴角速度 |
| w | 当前代码不使用；没有把这四列读成姿态四元数 |

本次字段映射：

```text
主机身 A：加速度传感器 + 陀螺仪传感器
副机身 B：acc1 + gyro1
```

用户确认主侧固定、副侧运动；具体字段配对由本次信号和时钟分组推断。Gyro 单位 rad/s 由用户确认；Acc 的 m/s² 依据静止约 9.8 的模长推断。

**主结果 Fixed complementary 实际只使用 Acc B 和 Gyro B。** 主 A 的两路用于审计及其他对照曲线，不能把主结果说成所有四路一起计算。

## 2. 把 CSV 变成四个时间序列，重复记录如何处理

读取时做：

```python
timestamp = int(row['timestamp_ns'])
xyz = [float(row['x']), float(row['y']), float(row['z'])]
streams[row['sensor']][timestamp] = xyz  # 同一路同时间戳，后写覆盖前写
```

实际代码还检查时间倒退、非有限值，并统计重复和冲突。

上面的两条 gyro1：

```text
第 6 行：1792119894952000000 → [0.0083,0.0418,-0.0036]
第 9 行：1792119894952000000 → [0.0083,0.0418,-0.0036]
```

含表头计行，它们指向同一采样。保留最后一条，第 9 行成为此采样的可追溯来源。它们不会产生两次角度更新。

若同一时间戳值不同，也保留最后一条并记录冲突。例如原文件另一处 gyro1：

```text

1792119897253000000 → [-0.0124,-2.3666,0.0090]
```

本次保留后一条。这无法恢复原本丢失的采样时序，是明确记录的有损处理。

清理后：

| 序列 | 唯一采样数 | 在模型中的用途 |
|---|---:|---|
| Acc A | 4956 | 主重力参考及双侧相位 |
| Gyro A | 4461 | 主运动速度及双 gyro 差分 |
| Acc B | 4102 | 副重力相位 |
| Gyro B | 4086 | 副轴向速度和主结果的更新时刻 |

总计 18306 行变为 17605 条唯一采样。此处没有做移动平均，没有把 Acc 和 Gyro 拼成一行后直接拟合角度，也没有做机器学习的 0～1 归一化。

## 3. 时间怎么处理：先得到秒，再构造同一时刻的输入

### 3.1 副 B 的时间

以本次副侧第一个采样时间为原点：

$$T_{B0}=1792119894952000000\ \mathrm{ns}.$$

每条副侧数据转换为：

$$t=(T-T_{B0})/10^9.$$

**先按整数相减，再换成浮点秒**，避免巨大纳秒值直接变浮点造成精度损失。

例如：

```text
1792119894952000000 → 0.000 s
1792119894965000000 → 0.013 s
1792119894980000000 → 0.028 s
```

本次前三个 Gyro B 更新的间隔就是 0、0.013、0.015 s，不能都写成 0.01 s。

### 3.2 主 A 的时间为什么需要另算

主侧时间约 5.42×10¹³ ns，副侧约 1.79×10¹⁸ ns，它们不是同一起点。主侧先减 `54192337235780` 得相对秒 tA，再转换：

$$t_{common}=1.000013369374\,t_A-0.014183239064.$$

这两个系数来自本次 CSV 前后记录顺序的鲁棒拟合：一条主记录附近的副记录提供近似对应时间，再拟合比例和偏移。它不是硬件同步，不能当成下一次录制可直接复用的常数。

固定底座主算法本身只需 B 两路时间。A/B 映射是四路对照和公共区间处理所需的另一步，不是把 Acc 转角度的公式。

### 3.3 Acc 和 Gyro 不同一时刻怎么办

本次在 **Gyro B 的实际采样时刻** 更新角度，将 Acc 插值到这些时刻。对 `t_left ≤ tq ≤ t_right`：

$$\lambda=\frac{t_q-t_{left}}{t_{right}-t_{left}},\quad a(t_q)=(1-\lambda)a_{left}+\lambda a_{right}.$$

原始记录中的一例：gyro 时刻 0.109 s，附近 Acc 为：

```text
t_left  = 0.104 s，a_left  = [-5.3383,-0.0169,-8.3875]
t_right = 0.125 s，a_right = [-5.3359,-0.0216,-8.3684]
```

权重 λ=(0.109−0.104)/(0.125−0.104)=0.238095238，得到：

```text
a(0.109) = [-5.337728571,-0.018019048,-8.382952381] m/s²
```

每个 XYZ 分量各自用同一个 λ。Acc B 插值括号跨度超过 0.1 s 时不插，不在数据区间外外推。

四路公共范围内，最后采用 4085 个原生 Gyro B 时刻。于是主算法看到的是：

```text
t[k]：该次更新的公共秒
g[k]：[gyro_x,gyro_y,gyro_z]，rad/s
a[k]：[acc_x,acc_y,acc_z]，m/s²，已对齐到 t[k]
```

## 4. “搭模型”具体搭了什么：参数、状态、更新规则

本次没有训练集拟合权重，没有 `.pt`、`.onnx` 或其他训练模型。物理模型包含三部分：

| 类别 | 内容 | 是否每条数据都重新估计 |
|---|---|---|
| 参数 P | 铰链轴 h、开启符号 s、gyro 零偏 bg、初始角 θ0、重力参考方向 e1/e2、参考模长 gref、时间常数 τ、门限 | 当前运行中固定 |
| 状态 S | 上一次融合角 θ、纯 gyro 积分角 I、上次时间 t、上次轴向速度 r、上次对齐 Acc a，以及有效性 | 每次更新后保存 |
| 更新规则 F | 积分预测＋Acc 观测＋质量判断＋互补修正 | 同一套公式反复使用 |

也就是：

$$S_k=F(S_{k-1},\underbrace{t_k,a_k,g_k}_{\text{本次输入}};P).$$

**后续数据起作用的方式是改变状态，不是重新训练一遍模型。**

当前代码的 `estimate_angle` 一次接收整段数组，内部循环递推。虽然递推式具备逐点更新形式，项目尚未把整套离线预处理封装为完整的实时传感器接入服务。

## 5. 参数究竟怎么从这份 CSV 得到

### 5.1 h：陀螺仪的哪个方向对应开合

理想铰链只有一个相对转动自由度。对本次基本固定的 A，B 的主要转动应围绕固定铰链轴。在 B 的自身坐标中，这个轴是 h。

本次先筛选副 Acc 的低动态样本，条件为模长 9.2～10.4 m/s²、jerk<15 m/s³。固定底座开合时，重力向量主要在一个平面内变化；对这些向量减中位数并作 SVD，最小奇异值的方向是平面法向。拟合得到约：

$$h_{plane}=(0.002375,0.999995,-0.001836).$$

因此正式输入取主坐标 `h=(0,1,0)`，即 Y 轴。活跃 gyro 的主方向分析另作核对，约 99.9319% 能量位于接近 Y 的方向。这里**使用了整段数据确认轴方向**，不是说只看第一行就自动知道轴。

本次开启时 Y 轴角速度为负，所以 `s=−1`。装反传感器或换设备之后，要重新确认轴与符号。

### 5.2 bg：前 1 秒估 gyro 零偏

取去重后 Gyro B 原生时间 `0≤t<1 s` 的 96 条读数，各轴分别取中位数：

$$b_g=\operatorname{median}_{0\le t<1}(g(t))=(0.00345,0.00020,-0.00085)\ \mathrm{rad/s}.$$

然后每个采样都计算：

$$g_c=g-b_g.$$

为什么：静止时理想 gyro 为零，实际剩余固定偏移，积久后会漂移。中位数只是零偏估计；若开头正在运动，它会把真实运动误当零偏。本次开头仍有轻微持握变化，这是一项初始化不确定性。

### 5.3 θ0：CSV 本身并没有写出初始开合角

Gyro 只能得到角度变化，必须有一个绝对初值。本次 θ0 来自视频约 1.233333～1.6 s 的原始投影角中位数：

$$\theta_0=33.253755^\circ.$$

所以本次不是“仅靠 CSV 自动认出开头 33.25°”。没有视频时，可以在已知闭合或已知展开的机械状态初始化；若任意角启动、也没有可用绝对观测，当前实现不能保证直接恢复绝对开合角。

### 5.4 e1/e2：Acc 转角度所需的参考坐标

在 Gyro B 对齐时刻的前 1 s，96 个 Acc 向量逐分量取中位数：

$$a_0=(-5.3909,0.016020584,-8.2248),\quad g_{ref}=\|a_0\|=9.834093477.$$

去掉沿铰链轴的分量：

$$p_0=a_0-(a_0\cdot h)h=(-5.3909,0,-8.2248).$$

归一化，建立垂直铰链轴平面中的两个参考方向：

$$e_1=p_0/\|p_0\|=(-0.548185470,0,-0.836356796),$$

$$e_2=-h\times e_1=(0.836356796,0,-0.548185470).$$

可以把 e1 理解为“初始重力在测量平面里的方向”，e2 为平面内与它垂直的方向。以后任意 Acc 投到这两个方向上，就能用 `atan2` 测它相对初始方向转了多少。

这个方法利用低动态重力，不需要先估完整三维姿态矩阵。加速度计实际测比力，动态加速度会污染它，后面必须判断可靠性。

## 6. 第一条输入到来，初始化了什么

第一个副 gyro 唯一采样：

```text
t=0 s
g=[0.0083,0.0418,-0.0036] rad/s
a=[-5.3981,0.0143,-8.2200] m/s²
```

扣零偏并投影：

$$r_0=(g-b_g)\cdot h=0.0418-0.0002=0.0416\ \mathrm{rad/s}.$$

保存初始状态：

```text
theta_previous = 33.253755°
pure_gyro_previous = 33.253755°
t_previous = 0 s
rate_previous = 0.0416 rad/s
acc_previous = [-5.3981,0.0143,-8.2200]
```

第一点没有经过时间，dt=0，积分量和校正增益都为零；输出就是 θ0。注意参数里的“前 1 s 中位数”要先拿到一段初始化数据才能确定：现有离线脚本在计算早期输出时已知道这段窗口，不能宣称开机第一瞬间就完成了这些标定。

## 7. 第二条输入：从原始行完整算到输出角度

原 CSV 第 12、13 行：

```csv
1792119894965000000,13.0,acc1,-5.3598,0.0095,-8.2942,0.0000
1792119894965000000,13.0,gyro1,0.0084,0.0349,-0.0032,0.0000
```

同一时间可直接配对，无需插值。时间为 0.013 s。

### 7.1 Gyro 预测：先算应该转多少

三轴扣零偏：

$$g_c=(0.0084,0.0349,-0.0032)-(0.00345,0.00020,-0.00085)=(0.00495,0.03470,-0.00235).$$

轴向速度：`r1=gc·h=0.0347 rad/s`。间隔 `dt=0.013−0=0.013 s`。

使用梯形积分，且本次正轴向速度代表闭合，开启角应减小：

$$\Delta\theta=-\frac{r_0+r_1}{2}\Delta t\frac{180}{\pi}=-\frac{0.0416+0.0347}{2}\times0.013\times\frac{180}{\pi}=-0.028415842^\circ.$$

预测角：

$$\theta^-=\theta_{previous}+\Delta\theta=33.253755-0.028415842=33.225339158^\circ.$$

### 7.2 Acc 观测：独立算一个重力角

当前 a=`(-5.3598,0.0095,-8.2942)`。投影到两个已确定的参考方向：

$$u=a\cdot e_1=(-5.3598)(-0.548185470)+(-8.2942)(-0.836356796)=9.875075021,$$

$$v=a\cdot e_2=(-5.3598)(0.836356796)+(-8.2942)(-0.548185470)=0.064054768.$$

相对重力相位：

$$\phi=\operatorname{atan2}(v,u)=0.006486419\ \mathrm{rad}.$$

由本次安装符号转成开合角：

$$\theta_{acc}=\theta_0-\phi\frac{180}{\pi}=32.882110594^\circ.$$

用两个投影和 `atan2` 保留相位象限；不是简单 `acos` 得到一个锐角。代码还将 θacc 加减 360° 的等价分支调整到预测角附近，避免 ±180° 相位边界跳变。

### 7.3 判断这个 Acc 角是否允许参与校正

| 判断 | 本点实算 | 是否通过 |
|---|---:|---|
| `abs(|a|−g_ref)<0.6` | `abs(9.875287−9.834093)=0.041194 m/s²` | 是 |
| 垂直铰链轴的 Acc 投影 / gref >0.2 | 1.004188 | 是 |
| `|a−a_previous|/dt<30` | 6.433810 m/s³ | 是 |
| `|g_c|<0.25` | 0.035130 rad/s | 是 |
| `abs(theta_acc−theta_prediction)<20°` | 0.343229° | 是 |

这些门限的目的：模长、jerk 和 gyro 速度尽量排除动态加速度污染；投影比例排除铰链平行重力时的不可观测情况；创新门限排除明显冲突。它们是当前工程规则，不是严格概率保证。

### 7.4 最后怎样融合

时间常数 τ=1 s，计算：

$$K=1-e^{-dt/\tau}=1-e^{-0.013}=0.012915865.$$

创新就是观测减预测：

$$innovation=32.882110594-33.225339158=-0.343228564^\circ.$$

应用的角度修正仅为：

$$correction=K\times innovation=-0.004433094^\circ.$$

所以最终输出：

$$\boxed{\theta_1=33.225339158-0.004433094=33.220906064^\circ}.$$

这就是 `imu/angles.csv` 中 `fixed_base_imu_angle_deg` 的第二行。Gyro负责本步短时运动，可信Acc只缓慢修正积分漂移；模型没有每一步直接跳到Acc角。

## 9. 如果新数据不可靠，模型怎样处理

门控未通过：本点仍可以依靠 gyro 预测，但不做 Acc 修正，即 `theta=theta_prediction`。

本次 t=2.003 s，去偏 gyro 模长 0.424376 rad/s，大于 0.25；尽管其他若干条件通过，仍拒绝 Acc 校正。输出 gyro 预测 36.277015203°，没有向当时 Acc 角 35.048523661° 拉动。

大时间缺口：超过 0.1 s 的 gyro 间隔不能默认已知期间怎么转，当前估计器置无效；之后仅在可信、低动态重力条件下恢复融合角。纯 gyro 累积在未知运动后不能凭空连续恢复。

铰链接近竖直：重力在测量平面中的投影很小，Acc几乎不随开合变化，拒绝其角度校正。这个阶段依赖gyro保持短时连续性，时间长了仍会漂移。

## 10. 双 IMU 模型在哪些公式上不同

固定底座主结果用 `r=(gB−bB)·hB`，隐含 A 不动。双 gyro 算法改成：

$$r=(g_B-b_B)\cdot h_B-(g_A-b_A)\cdot h_A.$$

这个 r 再代入同样的梯形积分和互补更新。为什么相减：相对角度只应受B相对A转动影响，理想情况下，两侧共同的整机转动轴向分量相消。

Acc 观测也不再只用 B：A、B 分别用各自初始Acc建立 e1/e2，各算 φA、φB，再计算：

$$\phi_{rel}=\operatorname{atan2}(\sin(\phi_B-\phi_A),\cos(\phi_B-\phi_A)),$$

$$\theta_{acc}=\theta_0-\phi_{rel}\,180/\pi.$$

两侧重力质量均需通过门控；双 gyro 还要求两侧 gyro 低动态。本次 bA=`(-0.00245,0.00155,-0.00030)`rad/s，hA暂按 `(0,1,0)`，未独立安装标定，因此双IMU结果仍是暂定基线。

当只保留 Gyro B 时，仍可用两侧Acc算相位，但积分没有了主gyro差分，任意手持下不能把A的转动假定为零。当只保留 Gyro A 时，本次模型只在低动态双Acc可信时输出角度，未实现高动态开合跟踪。

## 11. 后续 IMU 数据到底怎样用：要分两种情况

### 11.1 同一次连续采集，后面又来一个点

保持参数 P，保存并继承状态 S。对于新点 `t_new,a_new,g_new`：

```text
1. 按时间戳将 Acc 对齐到本次 gyro 时刻。
2. r_new = dot(g_new−bg,h)。
3. dt = t_new−t_previous。
4. delta = −0.5×(r_previous+r_new)×dt×180/pi。
5. prediction = theta_previous+delta。
6. phi = atan2(dot(a_new,e2),dot(a_new,e1))。
7. acc_angle = theta0−phi×180/pi，选最近的360°分支。
8. 判断重力质量、转动速度和创新。
9. 通过时 theta_new=prediction+(1−exp(−dt/tau))×(acc_angle−prediction)。
   否则 theta_new=prediction。
10. 保存 theta_new、t_new、r_new、a_new 和有效性，供下一步使用。
```

这描述的是已完成初始化后的数学更新，不是声称当前项目已经提供完整实时 `update()` 接口。Acc插值若依赖未来点，会引入等待；严格在线实现必须明确缓存、时间同步和延迟策略。

### 11.2 停止后重新采集另一份 CSV

**不能把这次所有常数原封不动套到下一次。**

| 项目 | 同设备下一次如何处理 |
|---|---|
| 读表、按 sensor 拆分、去重规则 | 字段及采集协议一致时复用 |
| 物理更新公式 | 适用机械条件一致时复用 |
| h 与开启符号 | 安装完全没变、已可靠标定时可复用；本次只是数据支持的暂定约定 |
| gyro 零偏 bg | 建议在新静止窗口重估；温度与时间可能使其变化 |
| 初始角 θ0 | 必须针对新起点确定；不能默认33.253755°或180° |
| 重力参考 a0、e1/e2 | 当前相位算法应在新起点、对应θ0的可信窗口重建；整机姿态变了不能照搬 |
| 时间戳原点、A/B时钟映射 | 按新采集重新建立或使用已验证的硬件时间协议 |
| 视频偏移 −1.217161 s | 仅属于本次录制；新视频需重新同步；仅做IMU时不需要这个视频偏移 |
| 上一融合角、上一速度等状态 | 新独立实验应重新初始化；没有跨断点连续性证据不能接着上一实验算 |
| τ=1 s 与门限 | 可作起点，但必须在新动态、设备和噪声下验证，不能保证普适 |

现有 `analyze_synchronized_experiment.py` 会读取本次视频，估时移与初角；它不是只换一个CSV就无需初始化的通用模型加载器。旧 `analyze_imu_log.py` 默认初始180°、前5s校准，同样不能在任意新日志上不检查就直接使用。

如果底座固定、开头可以已知0°或180°保持，后续无需每次都有视频即可使用这套递推思路；但需要让程序显式接收正确初值、参考窗口和标定。任意角开机、任意手持、不提供额外参考，则超出当前实现已验证的能力。
