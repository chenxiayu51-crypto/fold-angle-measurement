# keep-last 冲突处理敏感性分析（2026-10-20）

## 这份证据回答什么

原始传感器 CSV 中，同一整数纳秒时间戳有时会对应多条记录：

- 大多数是采集程序反复写入同一缓存值造成的**重复行**；
- 少数是同一时间戳对应**不同数值**的**冲突时间戳**。

项目采用 `keep-last`：每个时间戳保留最后一条。这份分析回答两个问题：

1. 冲突到底有多少？
2. 如果把规则换成 `keep-first`，最终结论会不会变？

## 文件

| 文件 | 内容 |
|---|---|
| `summary.json` | 两段日志的冲突计数、keep-first/keep-last 的流级差异、同步实验完整流程的指标差 |
| `keep_first_comparison_metrics.json` | keep-first 重跑得到的完整对比指标 |
| `keep_first_time_alignment.json` | keep-first 重跑得到的同步偏移与事件 |
| `keep_first_imu_summary.json` | keep-first 重跑得到的 IMU 摘要 |

## 方法

1. 按 `(sensor, integer timestamp_ns)` 分组，分别构造 keep-last 和 keep-first 两套序列；
2. 对陀螺序列，扣前 1 秒零偏后做梯形积分，比较最终角度和全程最大差；
3. 对加速度序列，按 +Y 轴做重力相位，比较冲突时刻的相位差；
4. 对同步实验，把 `imu_angle.read_log` 替换为 keep-first 版本，复用已有视频结果，在临时目录重跑完整 `analyze_synchronized_experiment.py` 流程；
5. 最终输出目录 `outputs/experiment_20261016_110453/` 没有被覆盖。

## 结论

- `keep-last` 是这份数据的合理工程约定，但不是理论上最严谨的处理；
- 对主结果（Fixed complementary）的影响约为 **0.00065°**，远小于 0.669° 本身；
- 纯陀螺积分对冲突更敏感，MAE 变化约 **0.096°**，但仍不改变“固定互补优于纯陀螺”的结论；
- 插值和滤波不是正确的第一反应：同一时间戳的冲突没有时间顺序，插值会发明数据，滤波会掩盖问题；
- 正确的长期修复在采集端：记录硬件事件时间戳、序号、时钟域和单位，避免缓存重复写入。
